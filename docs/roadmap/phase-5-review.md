# Phase 5 Review: Verified Findings

A whole-phase review of Phase 5 (`git diff dae940a..HEAD`) produced its candidate findings in groups; each group is verified here against the code, one at a time. A finding recorded here is confirmed unless its verdict says otherwise; none is fixed yet.

## How to continue

- **Status.** All candidates of the whole-phase review are verified here: groups 1-15 from its finders, 16 from its gaps-only pass. The finders' own reports are lost, so nothing outside this table is known. Refuted items stay in the table with their reason.
- **Decided.** 12b: check a factory's result against the position, so container proxies pass. 14b: an untyped `steps:` entry takes the context its class declares (§3.1.5 is rewritten). Items that predate Phase 5 are fixed all the same (4, 7b, 8b(i), 11b, 14a).
- **Fixes that share a change**, so one commit each: 7a with 8b(ii) (index inline contexts by id); 6a with 10c and 16a (one way to build an evaluation context, with the loader's class loader); 14a with the Phase 6 carried finding on re-typed step registrations; 1 with 15c (listener attachment and claim at declaration); 13a with 13b (load-time refusals and the schema's `minItems`). The rest stand alone.
- **Working agreement.** One commit per fix or group, stopping before each with a summary and a proposed message; the user reviews each with `/code-review`, and its findings are verified and reported with a verdict before anything is changed. A CLAUDE.md or `requirements.md` statement the change makes stale is corrected in the same commit. Pinned corpus messages (`# error:`) follow any wording change.
- **Practical.** Run `mvn -o clean test` from the root; `-pl transflux-yaml` alone resolves `transflux-core` from `~/.m2`, which may be stale. Probes: a single-file `Probe.java` run against `transflux-core/target/classes;transflux-yaml/target/classes` plus the dependency jars (`mvn dependency:build-classpath -pl transflux-yaml`); the review session's scratchpad probes do not survive it. On Windows, pass `MSYS_NO_PATHCONV=1` to `icacls`, and write Java or Groovy source through heredocs or the Edit tool rather than Python string literals, whose escapes mangle `\n` and `\|`.
